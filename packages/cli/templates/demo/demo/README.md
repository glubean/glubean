# Glubean public demo project

A runnable demo project that produces **real** flaky / regression data
for the public dashboard — not contrived examples. Generated by
`glubean init --template demo`.

## The narrative

Three independent data sources, each telling one story. Any one
breaking doesn't affect the others.

| Suite | Source | Story |
|---|---|---|
| `api-stable` | mock backend `/api/stable/*` (deterministic 200) | "Stable suite stays green over time" |
| `api-flaky` | mock backend `/api/flaky/*` (~30% 503) | "Glubean detects this API is flaky" |
| `contracts-stable` | mock backend stable shape | "Contract guards the API shape" |
| `canary` | in-process `Math.random()` (~50% pass) | "The run/reduce pipeline is alive — independent of any backend" |

## Profiles

| Command | Profile | Suites | Determinism |
|---|---|---|---|
| `npm test` | `local` | api-stable, contracts-stable | Always green (safe for a fresh clone) |
| `npm run test:public-demo` | `public-demo` | + api-flaky, canary, `--upload` | Intermittently non-zero exit BY DESIGN |

## Setup

Glubean loads `.env` into `ctx.vars` (+ `{{VAR}}` substitution) and
`.env.secrets` into `ctx.secrets` (auto-redacted). The caller key + the
upload token are secrets; the backend URL + project id are vars.

1. `cp .env.example .env` — set `MOCK_BACKEND_URL` to your deployed `glubean-demo-backend` (Cloudflare Workers; see that repo's README).
2. `cp .env.secrets.example .env.secrets` — set `DEMO_BACKEND_CALLER_KEY` to match the backend's `DEMO_CALLER_KEY` (so the api-stable/api-flaky tests authenticate as a verified caller).
3. For uploads (`npm run test:public-demo`): set `GLUBEAN_TOKEN` in `.env.secrets`. The upload TARGET is `profiles.public-demo.upload.projectAlias` in `glubean.yaml` (= `glubean-public-demo`) — that alias wins over `GLUBEAN_PROJECT_ID`, so to upload to your OWN project, edit the alias in `glubean.yaml`, not an env var.

`.env` and `.env.secrets` are gitignored — never commit them.

```bash
npm install
npm test                  # local profile — green
npm run test:public-demo  # full narrative — uploads to the public project
```

## Why a self-hosted mock backend?

Third-party public APIs (httpbin, jsonplaceholder) are deliberately
stable — they can't produce a believable "this API is flaky 30% of
the time" story. The companion `glubean-demo-backend` service provides
controlled failure modes that are realistic simulations of real
production scenarios, not contrived demo paths. See
`glubean/docs/05-demo-project-design.zh.md`.
