# Glubean public demo project

A runnable demo that produces **real** flaky / regression data — not
contrived examples. Generated by `glubean init --template demo`. Pairs
with the `glubean-demo-backend` service (a small Cloudflare Worker with
deliberate failure modes).

## The narrative

Three independent data sources, each telling one story. Any one
breaking doesn't affect the others.

| Suite | Source | Story |
|---|---|---|
| `api-stable` | mock backend `/api/stable/*` (deterministic 200) | "Stable suite stays green over time" |
| `api-flaky` | mock backend `/api/flaky/*` (~30% 503) | "Glubean detects this API is flaky" |
| `contracts-stable` | mock backend stable shape | "Contract guards the API shape" |
| `canary` | in-process `Math.random()` (~50% pass) | "The run/reduce pipeline is alive — independent of any backend" |

## Commands

| Command | Profile | Suites | Result |
|---|---|---|---|
| `npm test` | `local` | api-stable, contracts-stable | Always green (safe for a fresh clone) |
| `npm run test:full` | `full` | + api-flaky, canary | Intermittently non-zero exit BY DESIGN — that's the point |

`test:full` runs **fully local** — no cloud account, no upload. To
publish results to a dashboard, run `glubean login` once then
`glubean run --profile full --upload --project <your-project>`.

## Setup

```bash
cp .env.example .env     # set MOCK_BACKEND_URL to your glubean-demo-backend
npm install
npm test                 # local profile — green
npm run test:full        # full narrative — flaky + canary intermittently fail
```

`MOCK_BACKEND_URL` lives in `.env` (loaded into `ctx.vars` + `{{VAR}}`
templates). The HTTP client is configured once in
[`config/api.ts`](config/api.ts) and imported by every test + contract —
it auto-traces and auto-redacts requests, so the dashboard shows the
actual calls with zero hand-written client code.

`.env.secrets` (gitignored) is only needed for the opt-in `--upload`
flow — put `GLUBEAN_TOKEN` there.

## Notes

- **Retry is off by default.** The runner doesn't auto-retry 5xx — a
  verification test reports what the server actually returned (that's
  how the flaky suite catches 503s). Need resilience for a specific
  call? Pass `http.get(url, { retry: 2 })`, or set it for the whole
  shared client in `config/api.ts` via `configure({ http: { retry } })`.
- **Why a self-hosted mock backend?** Third-party public APIs (httpbin,
  jsonplaceholder) are deliberately stable — they can't produce a
  believable "this API is flaky 30% of the time" story. The companion
  `glubean-demo-backend` provides controlled failure modes that simulate
  real production scenarios. See `glubean/docs/05-demo-project-design.zh.md`.
